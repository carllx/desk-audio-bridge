# desk-audio-bridge 状态快照（2026-09-05）

## 当前状态

- Windows → Mac 扬声器路径：现场已报告达到稳定可听基线，当前候选为 `wasapi2src -> RTP L16/UDP -> Mac GStreamer -> MacBook Air Speakers`。
- 关键诊断结论：Mac 为多网卡环境时，接收端必须绑定实际直连接口地址；真实运行时地址不得提交仓库。
- Mac → Windows 麦克风路径：尚未完成。当前 Windows 普通应用仍没有可用的、由 Mac 内置麦克风驱动的输入端点。
- 人性化启动/停止：尚未实现；当前仍依赖两端手工运行命令。

## 当前计划

1. 先完成 Issue #6：Mac 内置麦克风采集 → 网络传输 → Windows 用户态接收；随后解决 Windows 可选择麦克风/input endpoint。
2. 双向链路稳定后完成易用性集成：一键/低操作成本启动、停止、状态检查与失败恢复。
3. 最后统一处理实验依赖与残留清理，不在诊断过程中边测边删。

## 当前已知问题

- 反向麦克风尚未形成 Windows 普通应用可选择的输入端点。
- 双向同时运行时存在潜在声学回授/回声风险，需要在完成单向 proof 后再处理。
- 启停流程仍不适合日常使用。

## 证据纪律

- 详细本地实验报告在入库前必须脱敏。
- 人耳端到端体验仍是最终验收 Gate。
